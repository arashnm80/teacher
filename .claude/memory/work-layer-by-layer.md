On large jobs (e.g. rebuilding the teacher book → markdown → site pipeline), break the work into a task list with time estimates, ask which to do, and work **layer by layer across the whole book** (all images, then all tables, then all translations…), not page by page or section by section.

**Why:** the user (2026-11-14) found a long page-by-page/batch-by-batch run too slow and had to leave mid-task without a usable checkpoint.

**How to apply:** start with a short plan + estimates; finish each layer completely before the next so every stop point leaves a coherent state.
